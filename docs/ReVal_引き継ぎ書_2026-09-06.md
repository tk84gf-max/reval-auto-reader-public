# ReVal 引き継ぎ書（使い方＋仕組みの全体像）

作成日: 2026-09-06 ／ 作成者: 高橋寛明（株式会社GoodFellow）／ 連絡先: 配布時に個別にお伝えします

---

## 1. この資料の位置づけ

ReVal（リバル）一式をお渡しするにあたり、「何が入っていて、どう動いていて、どこまで信じてよいか」を1冊にまとめたものです。

同梱の2本と役割を分けています。

| 資料 | 役割 |
|---|---|
| ReVal_できること紹介_友人向け.docx | 何ができるかの紹介（最初に読む） |
| ReVal_利用手順書.docx | Windows／Mac別のセットアップと操作手順（手を動かすとき） |
| **この引き継ぎ書** | 仕組みの全体像・計算の前提値・限界・渡していないもの（判断に使うとき） |

※お渡しするのは「マイソクの自動読み取り＋収益分析」の部分だけです。メールを監視して物件を自動で振り分ける仕組みは**含めていません**（第9章）。

---

## 2. ReValとは

- 不動産のマイソク（販売図面・物件概要書）を放り込むと、AIが数値を読み取り、年間CF・CCR・返済比率・CF率・積算評価・減価償却・税引後CFまで一気に算出するローカルアプリです
- 計算エンジンは TC Capitals の内製ツール「InvestGate+（IG+）」を原型に、2026年6月に新規構築しました。IG+の計算式と1行ずつ突き合わせ、16項目中15項目が一致することを確認しています（残り1項目の差は第8章）
- 手入力だけで使う「電卓」としても動きます。その場合APIキーは不要です
- 対象は**住居系の一棟収益物件**です。商業・テナント・借地権は注意表示は出ますが、数値は目安です

## 3. 全体像（何がどう動いているか）

### 3-1. 部品の役割

| ファイル | 役割 |
|---|---|
| ReVal自動読み取りを起動.bat ／ .command | 起動ボタン。Node.js でローカルサーバーを立ち上げ、ブラウザを開く |
| server.js | ローカルサーバー本体（localhost:5178）。Node標準ライブラリのみ・npm不要 |
| index.html | 物件カードを並べる作業画面。マイソクのドロップ・スクショ貼付・URL入力の受け口 |
| reval_core.js | 共通コア。AI（Anthropic API）にマイソクを渡して数値を抽出し、計算エンジンを呼ぶ |
| scripts/reval_calc.js | 計算エンジン（Node版）。全指標と格付けを算出 |
| scripts/prefill_reval.js | 物件ごとの ReVal.html を、抽出値を埋めた状態で生成 |
| ReVal.html | 計算エンジン本体（ブラウザ版・1ファイル完結）。電卓・35年シミュレーション・印刷用の想定収支表 |
| 初回設定_APIキー.bat ／ .command | APIキーを自分のPC内（~/.config/reval/apikey.txt）に保存する |
| analysis/ | 生成された物件別HTMLの置き場。自分のPC内だけ（配布物・Gitには含まれない） |

### 3-2. 処理の流れ

1. ブラウザにマイソク（PDF／画像／スクショ／公開ページのURL）を入れる
2. server.js が受け取り、reval_core.js が AI（モデル: claude-sonnet-4-6）に「価格・利回り・築年・延床・構造・住所・戸数」などを読み取らせる
3. 読み取り結果を画面で確認・修正（黄色＝AIが自信なし）
4. 確定した数値を scripts/reval_calc.js に渡して全指標を算出。同時に prefill_reval.js が物件別の ReVal.html を analysis/ に生成
5. 画面にカルテ、「想定／満室実数／現況実数」の3列比較、CCR順のランキングが出る
6. 「📎 詳細資料を追加」でレントロールやランニングコスト表を足すと、満室実数・現況実数の列が埋まる

### 3-3. 通信と保存先

- 外部に通信するのは**AI読み取りのとき**（マイソクの画像や本文と、あなたのAPIキーを Anthropic に送ります）と、**URL読み取りのとき**（指定したサイトに取りに行きます）だけ。計算・表示はPC内で完結し、**配布元（高橋）には何も届きません**
- 計算のたびに入力値をOSの一時フォルダに書き出して消しています。強制終了すると残ることがありますが、PC内にとどまります
- APIキーは ~/.config/reval/apikey.txt に置き、アプリのフォルダにもGitにも入らない
- 物件データは analysis/ と、ブラウザの localStorage（目標値・比較表の設定・入力保存）にだけ残る

## 4. 入手と初回設定

- **ZIPでお渡しします。** 展開したフォルダをそのまま使ってください（GitHubのリポジトリは非公開のため、そこからのダウンロードは不要です）
- Macの方: ZIPを展開したら、フォルダを「書類」など自分の場所に移してから、`.command` を右クリック→「開く」で起動します。「開発元を確認できません」と出たら、もう一度 右クリック→「開く」。それでも「権限がありません」と出るときだけ、ターミナルでフォルダに入り `chmod +x *.command` を実行します（この2つは別の問題です）
- Claude Code をお使いの方へ: Claude Code のログイン（サブスクリプション）と、このアプリのAPIキーは**別の契約**です。APIキーは Anthropic Console で別途発行してください
- 必要なもの: Node.js（LTS・無料）と Anthropic APIキー（従量課金・各自負担。マイソク1枚あたり数円程度）
- 手順の詳細は「ReVal_利用手順書.docx」の Windows／Mac の章を参照してください

## 5. 使い方（3分版）

1. 起動ファイルをダブルクリック → 黒い画面（ターミナル）が出てブラウザが開く。黒い画面は閉じない
2. マイソクをドロップ（複数可）。スクショは Ctrl+V（Macは ⌘+V）。公開ページならURL貼付も可
3. 数字を確認。違えば直す（自動で再計算）
4. カルテ・3列比較・ReValシミュレーターを見る。物件価格を動かすと賃料固定のまま利回りが変わる（指値の検討）
5. 金融機関に見せるなら ReVal.html の「印刷」で想定収支表を出す

## 6. 計算の前提値（標準セット）

マイソク1枚で回せるよう、融資・費用の条件は次の標準値を自動で使います。画面上でいつでも上書きできます。

### 6-1. 融資

| 項目 | 標準値 |
|---|---|
| 融資割合（LTV） | 90% |
| 諸費用 | 物件価格の7% |
| 金利 | 2.0% |
| 返済方式 | 元利均等（元金均等に切替可） |
| 返済期間 | 自動算出。残存耐用年数（法定耐用年数−築年数）が10年未満なら10年、それ以外は残存年数と30年の短い方 |

### 6-2. 法定耐用年数（住宅用）

| 構造 | 年数 |
|---|---|
| 木造 | 22年 |
| 軽量鉄骨（3mm以下） | 19年 |
| 軽量鉄骨（3〜4mm） | 27年 |
| 重量鉄骨（4mm超） | 34年 |
| RC・SRC | 47年 |

### 6-3. 収入

| 項目 | 標準値 |
|---|---|
| 有効率（延床に対する賃貸可能面積） | 80%（全構造共通） |
| 空室率 | 5% |
| 賃料下落率 | 年1% |

### 6-4. 費用

| 項目 | 標準値 |
|---|---|
| 管理委託料 | 実効賃料の5.5% |
| BM費（建物管理） | 200円／坪・月 |
| 水道光熱費（共用） | 50円／坪・月 |
| 建築費単価（保険・修繕の基礎） | 76万円／坪 |
| 火災保険 | 建築費の0.3%／年 |
| 固定資産税・都市計画税 | 実効賃料の10% |
| 修繕積立 | 建築費の0.5%／年 |
| 原状回復 | 1万円／坪（賃貸可能面積基準） |
| 入替率 | 25%／年 |
| 広告費（AD） | 1か月分 |

### 6-5. 税金

| 項目 | 標準値 |
|---|---|
| 税率 | 20% |
| 建物価格比率 | 70% |

### 6-6. 積算評価

| 項目 | 標準値 |
|---|---|
| 土地 | 土地面積 × 路線価（補正・倍率は1） |
| 建物 | 延床面積 × 21万円／㎡（劣化3級は24万円／㎡）× 残存率（1−築年÷法定耐用年数） |

## 7. 格付けと目標ライン

### 7-1. A〜D格付け（カルテの評価）

| 指標 | A | B | C | D |
|---|---|---|---|---|
| CCR（自己資金回収率） | 20%以上 | 15%以上 | 10%以上 | 10%未満 |
| 返済比率 | 50%以下 | 60%以下 | 65%以下 | 65%超 |
| CF率（物件価格に対する年間CF） | 2%以上 | 1.5%以上 | 1%以上 | 1%未満 |
| 積算比率 | 100%以上 | 80%以上 | 60%以上 | 60%未満 |

- 収入がゼロ（利回りも年収も不明）のときは、返済比率が0%になってAと誤判定しないよう強制的にDにしています
- 総合点（参考）: 私の環境では、CCR・返済比率・CF率を A=4／B=3／C=2／D=1 で足して**合計6点以上を「通過」**として、メール監視の足切りに使っています。**配布版の画面にはこの合否は表示されません**（計算関数は入っていますが呼ばれていません）。同じ基準で見たい場合は、カルテの3つの格付けを自分で足してください

### 7-2. 5軸メトリクスの目標ライン（画面表示用）

| 軸 | 目標 |
|---|---|
| 表面利回り | 9.0%以上 |
| NOI利回り | 6.5%以上 |
| CF率 | 1.5%以上 |
| 返済比率 | 50%以下 |
| 積算比率 | 90%以上 |

- これは画面のバーに引く「達成／未達」の線で、上の総合点（足切り）とは**別物**です。混同しやすいので注意してください
- 「⚙目標値を編集」で自分の基準に変更できます（ブラウザに保存）

### 7-3. 期間×LTVの組合せ比較表

- ReVal.html のメトリクス直下に、返済期間（既定20／25／30年）×融資割合（既定90／100%）の組合せ表を常設しています
- いま入力中の条件と一致する行に印が付き、CFの正負で色分け。耐用年数を超える期間には※が付きます
- 「⚙編集」で期間・LTVを変更できます（各8個まで。印刷には出ません）

## 8. 注意点と限界（ここは必ず読んでください）

1. **AI読み取りは必ず目で確認する。** 黄色の項目は自信なしの印です。価格・利回り・面積・築年・構造が違うと全部ずれます
2. **IG+との唯一の差＝原状回復費の面積基準。** IG+は延床坪、ReValは賃貸可能坪（延床×有効率）で計算します。実態重視でこのままにしています。その分、ReValのCFはIG+より少し高め（楽観側）に出ます
3. **現況実数の列は、画面（ReVal.html）と内部計算（reval_calc.js）で費用の扱いが少し違います。** 画面は現況賃料ベースで費用を再計算、内部は満室時の費用を流用します。差は年数万〜十数万円程度。金融機関に「現況」を見せるときはどちらの定義かを意識してください
4. **URL読み取りは公開ページのみ。** 楽待・健美家などログインが要るページは取れません。その場合はスクショを貼ってください
5. **自動で出る警告は3種類。** 旧耐震（築年から竣工年を推定、1981年以前＝赤）、商業・テナント（物件名・用途・レントロールから検知）、借地権（定期借地は強めの警告）。警告は「気づき」であって数値の補正はしていません
6. **土地の積算には路線価が要ります。** マイソクに無ければ土地部分は未算定（建物部分だけ）になります。公示地価などからの推定はしていません。路線価を手で入れれば土地も計算されます
7. **投資判断の補助です。** 最終判断はご自身の責任でお願いします

## 9. 渡していないもの（配布版に含まれない仕組み）

私の環境では次の仕組みも動いていますが、個人のメール・物件データと結びついているため**配布版には含めていません**。必要になったらご相談ください。

| 仕組み | 内容 |
|---|---|
| メール自動監視 | Gmailの物件メールを定期チェックし、本文・添付マイソク・リンク先から自動で分析。総合6点以上を通知し、Gmailラベルを付ける |
| 地場業者サイトの巡回 | 地元の不動産会社サイトの新着を検知して同じ分析にかける |
| 分析履歴のExcel台帳 | 分析するたびに履歴を追記し、元メール・マイソク・カルテにリンクで飛べる台帳を作る |
| 通過物件の自動保存 | 足切り通過物件の判断材料一式を専用フォルダに自動保存 |
| Claude Code スキル（bukken-hyoka） | AIアシスタントに「この物件どう？」と聞くだけで同じ計算を回す仕組み |

## 10. データと費用

- **費用**: AI読み取りだけ従量課金（各自のAPIキー＝各自の負担）。電卓機能は無料
- **データ**: 物件データもAPIキーも、配布元（高橋）には一切届きません。外に出るのは AI読み取り時の Anthropic への送信と、URL読み取り時のそのサイトへのアクセスだけです（第3章3-3）
- **バックアップ**: analysis/ フォルダとブラウザの設定（localStorage）が消えると、生成したカルテと目標値設定は失われます。残したいカルテはHTMLごと別の場所に控えてください

## 11. 困ったとき

| 症状 | 対処 |
|---|---|
| 「APIキー未設定」と出る | 初回設定ファイルで鍵を貼って保存したか確認 |
| 「Node.js が見つかりません」 | Node.js（LTS）を入れる。入れた後はPC再起動またはターミナルを開き直す |
| ブラウザが開かない | 自分でブラウザを開き、アドレス欄に localhost:5178 |
| 読み取りがおかしい | 数字は手で直せます。マイソクの解像度が低いと誤読が増えます |
| 黒い画面を閉じてしまった | 起動ファイルをもう一度ダブルクリック |
| Macで「開発元を確認できません」 | 右クリック→「開く」→もう一度「開く」 |

## 12. 更新と改造の方針

- **本体の更新**: 配布元リポジトリを更新したら、ZIPを取り直すか git pull で取り込めます（analysis/ とAPIキーは上書きされません）
- **自分用に改造したい**: GitHubで Fork するか、ReVal.html をメモ帳で開いて費率を書き換えてください。ReVal.html は1ファイル完結にしてあるのはそのためです
- **改造時の落とし穴**: 同じ計算式が ReVal.html（ブラウザ版）と scripts/reval_calc.js（Node版）の2か所にあり、法定耐用年数の表は prefill_reval.js を含めて3か所にあります。片方だけ直すと画面とカルテの数字がずれます。数値を変えるときは全部を揃えてください
- **質問・不具合**: 配布時にお伝えした連絡先へ。物件名や金額を含む相談は、マイソクではなくスクショの一部など、必要最小限で送ってください
